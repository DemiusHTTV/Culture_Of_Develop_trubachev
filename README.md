# 🛠 Культура Разработки (Задания и Практика)

Данный репозиторий содержит решения домашних заданий и материалы аудиторных практик по курсу "Культура разработки". Цель материалов — научиться выстраивать воспроизводимые, предсказуемые процессы сборки, тестирования и развертывания кода.

---

## 📚 Структура репозитория

Репозиторий разделен на две основные части: **аудиторную практику** и **выполненное домашнее задание**.

### 1. 🎓 Аудиторная практика (в корне проекта)

В корневой директории находятся файлы, с которыми мы работали во время занятий, изучая возможности утилиты `make`:
- **[`Makefile`](./Makefile)** — базовые примеры таргетов и ознакомление с синтаксисом Make.
- **[`MakePracticefile`](./MakePracticefile)** — расширенная практика и эксперименты с различными возможностями, цепочками и переменными.

Эти файлы служат песочницей и справочником по базовым функциям сборщика.

---

### 2. 🏠 Домашнее задание: Автоматизация с помощью Make

В папке **[`make_homework/`](./make_homework/)** находится полноценный проект, демонстрирующий правильные подходы к автоматизации рутинных задач. `Makefile` здесь выступает в качестве единой точки входа для управления проектом.

#### 🌟 Ключевые идеи и решения:

- **Единая точка входа**:
  Пользователь или CI/CD система не должны знать точные команды для запуска линтеров или тестов. Вместо запоминания десятков флагов (например, для `black` или `mypy`), достаточно выполнить `make lint` или `make check`. Сложность инструментов инкапсулирована.

- **Stateless-подход и управление окружением**:
  Проект не полагается на глобально установленные пакеты системы. Используется локальное виртуальное окружение `.venv/`. В `Makefile` жестко прописаны абсолютные/относительные пути к исполняемым файлам (например, `$(VENV)/bin/python`). Это гарантирует исполнение команд в контексте проекта, даже если окружение не активировано через `source`.

- **Автоматизация проверок качества (QA)**:
  - 📦 **Зависимости**: `make check-requirements` сканирует исходный код на импорты и сверяет их с `requirements.txt`.
  - 🛡 **Типизация**: `make typecheck` запускает `mypy` для статического анализа типов, выявляя баги до запуска кода.
  - ✨ **Стиль**: `make format` и `make lint` приводят код к стандарту PEP 8 с помощью `black`.

- **Композиция действий (Граф зависимостей)**:
  Make позволяет выстраивать цепочки выполнения. Цель `make check` зависит от `typecheck`, `check-requirements` и `lint`. Одним вызовом `make check` запускается весь комплекс проверок!

> **Подробнее:** Инструкции по запуску домашнего задания и детали реализации можно найти в [документации самого проекта](./make_homework/README.md).
