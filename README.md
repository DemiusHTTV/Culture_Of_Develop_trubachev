# Культура Разработки (Домашние задания)

Данный репозиторий содержит решения домашних заданий по культуре разработки. 

## [Задание: Автоматизация с помощью Make](./make_homework/)

В папке `make_homework` находится проект, демонстрирующий подходы к автоматизации рутинных задач с помощью `make`. 
Современная разработка требует от нас не просто умения писать код, но и умения строить воспроизводимые, предсказуемые процессы его сборки, тестирования и развертывания. `Makefile` выступает в качестве единой точки входа для управления проектом.

### Ключевые идеи и решения:

1. **Единая точка входа**:
   Пользователь или CI/CD система не должны знать точные команды для запуска линтеров, тестов или сборки. Вместо того, чтобы запоминать десятки флагов для `black`, `mypy` или `pytest`, достаточно выполнить `make lint` или `make test`. Это инкапсулирует сложность инструментов внутри проекта.

2. **Stateless-подход и управление окружением**:
   Частая ошибка — полагаться на глобальное состояние системы (например, глобально установленные пакеты). В данном проекте используется локальное виртуальное окружение `.venv/`.
   В `Makefile` жестко прописаны пути к исполняемым файлам окружения (например, `$(VENV)/bin/python`). Это гарантирует, что команды будут исполняться именно в контексте проектного окружения, независимо от того, активировал ли пользователь окружение через `source`.

3. **Автоматизация проверок качества (QA)**:
   - **Зависимости**: Цель `make check-requirements` сканирует исходный код на предмет импортов и проверяет, что все они явно указаны в `requirements.txt`.
   - **Типизация**: Цель `make typecheck` запускает `mypy` для статического анализа типов в Python, выявляя ошибки вроде сложения строки с числом до запуска кода.
   - **Стиль**: Цели `make format` и `make lint` автоматически приводят код к стандарту PEP 8 с помощью `black` и проверяют его.

4. **Композиция действий (Граф зависимостей)**:
   Make позволяет выстраивать цепочки выполнения. Цель `make check` зависит от `typecheck`, `check-requirements` и `lint`. Таким образом, одним вызовом `make check` мы запускаем весь комплекс проверок. 

Более подробную информацию и инструкции по запуску можно найти в [документации самого проекта](./make_homework/README.md).
